Workflow

From one file to five platforms

The application is a desktop program that runs on macOS. Nothing is published automatically: every post starts with the account owner selecting a video and pressing publish.

Publishing a video

A normal post takes six steps.

  1. Choose the brand

    The operator selects which of their own content brands the post belongs to. That choice determines which set of connected accounts and credentials the app will use.

  2. Select the video

    A short-form clip is chosen from the local disk. The app checks its aspect ratio, duration and codec, and warns if a platform would reject it.

  3. Write the caption

    One title, one description and one set of hashtags are written. The app then adapts them to each platform's character and hashtag limits.

  4. Choose a cover

    A frame from the video is picked as the thumbnail, or a separate image is uploaded. Covers are generated in the size each platform expects.

  5. Pick the destinations and mode

    The connected accounts are selected. A draft mode is available, which publishes as private or unlisted so a post can be checked before it goes public.

  6. Publish or schedule

    The post goes out immediately, or is queued for a chosen time. Each platform's result — link or error — is written to a local history log.

How each platform receives the video

Every integration uses the platform's own official API. No unofficial endpoints, scraping or browser automation is involved.

YouTube

Uploaded through the YouTube Data API as a Short, with the chosen thumbnail.

Instagram & Facebook

Published as Reels through the Meta Graph API. These platforms fetch the video from a temporary local address rather than from a stored copy.

Threads

Published as a video post through the official Threads API.

TikTok

Uploaded with the TikTok Content Posting API. The file is sent directly to TikTok by the app, and the post is created on the operator's own account.

Keeping brands separate

The application can be used for more than one of the operator's content brands. Each brand's access tokens and settings are stored in their own separate location on disk, and a publish only ever uses the credentials of the brand chosen for that post. Nothing is shared between brands.

Where the data lives

The application has no backend service. Videos, captions, publish history and platform access tokens are stored on the operator's own computer. Nothing is sent anywhere except to the social platforms the owner has connected, and only when a publish is started.
